# 剧场客服来信分流验收

用留出件比较来信分流与多数类基线，核对各队列负载和人工分诊量。

栖桥剧场观众服务中心，四名客服为大小两个剧场处理票务、无障碍服务和失物招领来信。 客服从共享邮箱导出去标识的来信，主管复核归口并冻结训练批和留出批。运营专员用训练批建立各队列的文本质心，在留出批核对错投及人工分诊，再把逐件验收明细交给票务组、观众服务组和前厅组定排班。

- 演出取消后退改来信占比上升，总体命中率容易掩盖失物和无障碍请求的错投。
- 历史邮件和验收批混用时，当天才出现的新词会提前影响词表和权重。
- 短句或多诉求邮件容易错投，一线需要知道哪些来信应转人工分诊。

## 业务模块

| 模块 | 用途 |
|---|---|
| 值班总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 来信明细 | 下载「栖桥剧场来信分流_20261120.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 分流验收 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 分流结果 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 验收复核 | 查看待处理或已完成记录。复核主管可提交验收决定及依据。 |
| 归口更正 | 已交付运行的留出件归口更正、撤回与版本链，重算后页面与下载一次性切换。 |
| 分流交付 | 按批查找结果，核对复核状态并下载当前生效版本的 CSV。 |

## 演示流程

1. 11 月 20 日 09:00，从共享邮箱整理「栖桥剧场来信分流_20261120.csv」，保留各件的归口和固定批次。
2. 导入后核对 18 封来信，其中 11 封训练件、7 封留出件。
3. 使用完整训练词表及 0.12 最低相似度运行验收。
4. 在分流结果中比较宏 F1 与训练多数队列的基线，并查看自动分流覆盖率。
5. 逐件检查 QQ-TEST-07 的新词来信和人工分诊原因，核对三组的预计来信量。
6. 将最低相似度调到 0.30，沿用同一批次重跑，比较覆盖率和错投。
7. 主管在验收复核页记录放行或复测决定，在交付页导出逐件分流明细。

## 计算口径

- CSV 明确标记 train 或 test。训练件拟合词表、逆文档频率、各标签质心和多数类。留出件只参与预测与验收计分。
- 连续汉字取相邻双字词，单字保留。英文字母和数字按连续串取词并转小写。仅保留训练中出现的词，限制词量时按训练文档频率降序、同频按词序取前 K 个。
- 以词频乘以 1 + ln((1 + 训练件数)/(1 + 训练文档频率)) 并做 L2 归一化。各类取归一化训练向量的均值，与留出件向量计算余弦相似度。
- 无命中词、最高分并列或低于阈值时转人工。最高余弦分衡量接近程度。训练多数类并列时按队列名称排序取首项。
- 两种策略共用训练标签与留出标签的并集计算宏 F1，零分母计零。人工分诊计入真实队列的漏分，覆盖率按自动分流量除以留出总量计算。

## 归口更正与版本切换

留出件交付后发现归口有误时，在「归口更正」页基于已通过复核的原始运行发起。更正只覆盖留出件的人工归口，训练词表、IDF、质心、阈值和多数类基线全部沿用原运行，因此逐件预测去向（predicted、相似度、判定依据）保持冻结，仅受影响来信的真实归口与计分发生变化。

- 更正按「复核号」登记，同一运行链上复核号唯一，修订序号在链上递增。同封来信的有效归口由事件链按修订序号取最新一条。
- 一次更正可同时提交多封来信；同封来信在同一批中出现冲突归口时整批退回，不落库也不产生重算。
- 撤回指定更正会把该批标记为 `withdrawn` 并追加一条撤回事件，重放剩余事件后归口恢复到上一条有效更正（没有则回到原始归口）；撤回先到达也会触发一次重算。
- 重算沿用原数据批次与参数排队执行，重算版本不进入复核与交付列表。只有最新一次更正的重算才能切换版本，过期重算标记失败且不重复计分。
- worker 先写好新版结果与 CSV，再在同一事务内翻转 `current_run_id` 指针并回写更正批次：结果页面和下载一次性切换到同一完整版本；中断或失败时指针不动，旧版继续可用。原始运行与全部历史版本仍可按运行 ID 查看和下载。
- 接口为 `GET/POST /api/corrections/runs/{run_id}` 与 `POST /api/corrections/{batch_id}/withdraw`，分析员和复核主管可写，只读角色可查看。
- 离线规则验证：`python -m scripts.test_corrections`（覆盖事件链、撤回恢复、整批退回、基线冻结与版本指针等 11 项断言）。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
